# 전체 UI 구현 메모

기준: 제공된 KICK-X 요구사항 정의·분석 명세서 2종, 프로젝트 제안서, 2026-09-25 인수인계 텍스트 및 기존 홈 시안.

## 화면과 요구사항

| 요구사항 | 확인할 화면 |
| --- | --- |
| FR-PLAYER-01~03 | 선수 탐색 / 선수 상세 / 기간별 시세 그래프 |
| FR-TRADE-01~05 | 선수 거래 확인 창 / 내 자산 / 거래 내역 |
| FR-SQUAD-01~02 | 스쿼드 포지션 선택, 보유 선수 배치, 저장 |
| FR-ASSET-01~05 | 자산 합산 / 손익 / 예시 기간별 랭킹 / 재입장 시 자산 유지 |
| FR-COMM-01~05 | 구단·선수 라운지, 글·댓글, 본인 거래 첨부, 작성 제한 |
| FR-ADMIN-01~04 | 데이터 처리 상태 / 실패 작업 재처리 시연 / 거래 및 신고 검토 |
| NFR-USE | 1366px 이상 데스크톱 공통 내비게이션, 모바일 보조 레이아웃, 오류·빈 결과 안내 |

이 표는 UI와 시연 흐름의 대응 관계이며 서버 요구사항의 완료 판정이 아닙니다. 예를 들어 FR-TRADE의 실제 DB 원자성이나 FR-AUTH의 OAuth 세션은 아직 구현 전입니다.

## 시연 순서

1. 홈에서 선수 시장으로 이동합니다.
2. 보유하지 않은 `라민 야말`을 검색하고 상세 화면에서 매입합니다.
3. 내 자산과 거래 내역의 변화, 새로고침 후 유지를 확인합니다.
4. 스쿼드의 FW 자리를 선택하고 야말을 배치한 뒤 저장합니다.
5. 구단 라운지에서 글을 쓰며 본인 거래를 첨부합니다.
6. 글 상세에서 댓글·수정·삭제·신고를 확인합니다.
7. 다른 구단 라운지에서 작성 제한을 확인합니다.
8. 운영 관리에서 실패 작업 재처리와 신고 숨김·기각을 확인합니다.
9. 마이페이지에서 프로필을 변경하거나 데모 초기화를 수행합니다.

## 후속 실제 연결

인증과 `profiles` → 선수 조회 저장소 → 서버 거래 서비스 → 선수단/커뮤니티 저장 순으로 현재 데모 경계를 교체할 수 있습니다. Performance와 가격은 별도로 유지하고, API 키는 클라이언트 코드에 넣지 않습니다. 게임 규칙 미확정 값은 실제 연결 전에 팀에서 확정해야 합니다.
